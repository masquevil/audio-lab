这个项目目前的状态是从别的项目 copy 过来的，几乎所有的文件都没有用。

之所以 copy 过来，是我希望保留一些上一个项目的基础能力，比如 src 目录下的文件结构，比如 deploy 脚本等等。

我现在只新建了两个目录，一个是 features，一个是 .cline/skills。

## features 目录

这个目录我计划是写下我的产品需求，交由 AI 实现。

可以理解为这个目录的我扮演产品经理的角色，每一个需求文档就是一次需求评审会议，AI 需要扮演研发的角色进行需求评审、进行相关的准备然后开发。

按照人类公司的流程大概是这样：

1. PM 出具需求文档
   1. 发给研发 leader 进行大致沟通，确定方向、可行性等等
   2. 发给 UI/UE 进行大致沟通
   3. 发给研发浏览，让他有一个大概的印象
2. 需求评审会议，拉上相关的人，PM、UI/UE、研发、研发leader、QA
   1. 明确需求细节，研发心里要有一个大致的方案
   2. 明确交付内容，进行估时
3. 可选：技术评审 —— 当项目复杂度较高、估时较长时，研发需要发起技术评审
   1. 研发出具技术评审文档
   2. 研发拉上研发 leader 和其它相关方（后端、UI 等）进行技术评审会议
   3. 确定所有细节方案
4. 研发进行开发
   1. 提交代码需要其他研发进行 code review
5. 研发完成后交由 QA 测试
   1. QA 依据需求文档和明确的交付内容进行测试
   2. 研发根据 QA 的反馈进行修改
6. 研发交由 PM 最终验收
   1. 通常来说这里已经没问题了，如果有一些细节修改，则回到 4
   2. 极少数情况，如果有大的变动，则需要回到 1

我列出这个流程是想给 AI 后续工作流做一个参考，但是不要照搬：

1. 首先这个流程是我记忆里的，也有可能不准确
2. 然后里面有些内容可能对于 AI 来说是多余的
3. 然后对 AI 来说可能还会需要额外的步骤

## 这个项目是做什么的

这个项目我打算围绕 web audio api 展开，实现一些很酷的功能，比如：

1. 基础功能
   1. 模拟各种乐器
   2. 模拟人声
   3. 模拟自然环境声音
2. 延伸功能
   1. 模拟乐器 -> 可以组合编曲、保存
   2. 模拟人声 -> 可以读出用户输入的任何一段话，可以通过简单的参数调整音色（比如 雄性-磁性滑块、年龄滑块 等等）
3. 其它
   1. 比如分析音乐的波形，推荐相似的音乐（比如都是悲伤的音乐）

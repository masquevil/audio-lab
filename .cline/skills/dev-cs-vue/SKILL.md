# 开发时的实现约束

开发依据 [CONTRIBUTING.md](../../../CONTRIBUTING.md#代码规范基线)、需求和相关代码。默认不加载 code-review checklist；有具体疑问时仅查对应条目。复用未变且仍在有效上下文中的内容，不因阶段切换重复全文读取。

- 修改组件或逻辑时应用「Vue 与 TypeScript」，修改样式时应用「样式」，修改文档时应用「文档」；不在 skill 中复制具体规范。
- 新增或迁移文件前按「目录结构与职责」确定归属，页面私有逻辑就近放置。
- 生成实现前应用「设计与职责边界」「命名与代码组织」：先确定状态、契约和副作用归属，再选择最小必要抽象；返修先检查相关调用链，不只修用户指出的一行。
- 实现交互时同步处理失败、异步竞争、可访问性和资源释放；涉及音频时按需加载 web-audio。
- 按最小可验证实现推进，依开发指南设计和实现，随改动验证；不把已知问题留待 review。交付前由 code-review 加载详细清单审查最终代码的技术质量，研发另行执行工程检查及行为验证，两者结论分开。

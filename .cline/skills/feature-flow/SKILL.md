# 需求到交付

1. 读 AGENTS.md 与关联需求、代码、配置、Git 状态。按 features/README.md 建立或更新单份实施记录，避免分散计划和测试报告。
2. 按 features/README.md 完成需求评审与按风险触发的技术评审；有实质选择时等待 PM 确认，不把宣布方案视为确认。明确纠错及已批准范围内的普通细节直接处理；新重要取舍回到评审。
3. 开发时加载 dev-cs-vue，按最小方案实现与验证；涉及音频再加载 web-audio，测试策略匹配风险，不为形式引入框架。
4. 开发完成后、交付 PM 前加载 code-review，统一审查本次变更，实际执行检查，失败先修复或明确阻塞。返修后检查受影响范围。
5. 在实施记录中写验证结果及未覆盖项，状态置待验收，给 PM 可操作的验收步骤；PM 确认后才清理当前索引。

只保留可复用结论，不生成会议角色扮演、重复报告或无用的精确估时。文档规则引用现有入口；修改 skill 时检查是否与其他规则重叠或冲突。

# 参考驱动的环境声合成

本文件记录一套可复用的方法：给定若干段真实录音，合成**同类的、全新的**声音实例，并用可复现的方式判断做到什么程度。

适用对象：雷、雨、风、火、脚步、机械等以噪声/纹理为主的声音。对人声、乐器这类有明确音高与发音机制的声音，范式不同（参见声码器/物理建模），本方法只能覆盖其中的噪声成分。

## 1. 先明确任务类型

| 任务 | 判据 | 是否适用 |
| --- | --- | --- |
| 复制某一段录音 | 逐样本比对（相关性、SNR、对数谱距离） | 适用，但通常不是你想要的 |
| 生成同类的新实例 | 分布检验 + 人类标注判定 + 听测 | **本方法的目标** |

声音不存在"逐像素比对"式的验收：两段真实雷声之间，波形最大归一化相关也只有 **0.06**（实测 event-1 vs event-3 = 0.067，vs 另一段 1299 = 0.057），和"生成 vs 真实"的 0.058 是同一量级。所以复制式指标在这里没有分辨力。

## 2. 三层验证，各自只能证明一件事

1. **波形层**（相关、SNR）：只用于确认"能否复制某一段"，不能用于判断"像不像"。
2. **特征包络**（逐频段包络、包络统计、调制谱、tonality）：验证"是否落在真实样本的取值范围内"。**必要但不充分**——本方法里出现过 15 维全部落在真实范围内、听感仍然不对的情况。
3. **人类标注模型**（AudioSet/AST）：验证"人会把这段叫什么"。它只是代理，不是耳朵：真实雷声的 P(Thunder) 实测为 **0.001–0.895**（中位 0.373），因此**不能用固定阈值，只能和参考集比较**。

结论：三层都要过，最终仍以人耳听测为准。任何一层都不足以宣布"做好了"。

## 3. 流程

1. **建参考集**：同一类声音至少 6–10 段，覆盖不同距离/强度/录音条件。参考音频只放本地（`.ai/` 或任意忽略目录），不进仓库。
2. **分析**：`tools/sound/measure.py` 输出每段的 A/B 结构、频段配比、衰减率、调制谱；`tools/sound/acceptance.py` 给出各维度的取值范围。
3. **临摹验证**（关键）：先证明"引擎 + 表示"足够。用 `tools/sound/imitate.py` 把一段录音分解成 24 段 1/3 倍频程 × 20ms 的包络，再用噪声重建。实测可达平滑包络相关 0.967–0.990、整体误差 2.6–3.3 dB，P(Thunder) 与原声同档（如 0.26→0.31）。**临摹不过关，说明引擎或表示有问题，先修这一层。**
4. **拆解结构**：A（起爆）/ B（持续）分别定量，得到可复现的参数（见 [measurements](measurements.md)）。
5. **模板化生成**：把参考的时频结构压成紧凑模板（24 × 20ms，1dB 量化，base64），运行时用分块 STFT 铺随机相位重建，靠时间伸缩/频谱倾斜/增益/随机种子产生新实例。模板是**参数数据，不是音频**。
6. **验收**：三层判据 + 浏览器实测（见 §5）。

第 3 步不可跳过。跳过它的直接后果是：所有精力都花在"调参数"，而不知道引擎能不能表达目标声音。

## 4. 已踩过的坑

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 频谱完全对齐，听感像"炸麦" | 逐频段独立噪声按帧增益拼合 = 保留幅度谱、随机化相位，瞬态被抹掉 | 用真实录音的逐频段包络驱动同一引擎（判定 0.59–0.86），说明问题在结构而非引擎 |
| "像敲锣"，有稳定音高 | 等间距辐射元 → 固定到达间隔（6m / 343m·s⁻¹ = 17.5ms）→ 57Hz 谐波列 | 分层采样（每层随机取一点）：层内随机破坏周期、每层必有一点避免空隙 |
| 自相关峰值 0.4–0.9（窄带/音高） | 稀疏到达或孤立脉冲；窄带噪声本身也会抬高该指标 | 目标为 0.18–0.24、>0.5 的帧 ≤3%；末尾孤立脉冲要截断并淡出 |
| 听起来像鼓/打击乐 | 把连续的起伏做成离散 roll（20ms 起音、45ms 间隔的脉冲串） | 起伏必须是**连续随机过程**（相关时间 ~45ms），不能是离散敲击 |
| 高频嘶声、整段像噪声 | 单级低通不足以压制高频：2.5–5kHz 带宽是 150–300Hz 的 16 倍 | 三级低通，或直接按频段能量分配 |
| "一层噪声被整体调音量" | 所有频段共用一条包络；真实录音的各频段与总包络相关仅 0.59–0.93 | 频段独立成分占比 ~0.6；高频衰减率高于低频 |
| 起爆像"打沙袋" | 起爆的"身体"只做单级低通 1500Hz；头部还留了 150ms 静音 | 三级低通 + 头余量 ≤10ms；起爆频谱以 100–400Hz 为主、3.2kHz 以上低 30dB |
| 判成"爆炸/喷发"而不是雷 | 起爆瞬态过强、持续段过短或衰减过快 | 起音 0.4–1s 缓慢涌起；B 段衰减 -1~-4 dB/s；时长 8–18s |
| 底噪里有雨声 | 模板来自夹带雨声的录音 | 只对 **>800Hz** 做固定底噪谱减（分位数法）；全频段谱减会削薄 30–800Hz 的主体 |
| A/B 接缝不舒服 | 对本来就连续的两段做交叉淡化，等于混合两段不同内容（实测判定 0.29→0.20） | 默认直接拼接；交叉淡化只作为人为改接缝的可选开关 |
| 起爆处"轻微失真" | STFT 块长 2048 点（42.7ms）抹开瞬态 | 块长降到 1024（21ms），判定 0.31→0.46 |
| 判定脚本窗口数不同导致分数差异 | 判定按 10 秒窗口平均，19.96 秒与 20.96 秒的文件窗口数不同（1 个 vs 2 个） | 比较时先补齐到同一时长，或固定窗口数 |
| 低强度下“噼啪太密” | 等功率交叉淡化时，密集事件纹理（旺火每秒 10 次）在 0.4 强度仍有约 10%（-20dB）混入 | 给事件纹理设强度阈值（0.45 以下完全关闭），不要只靠交叉淡化 |
| 窄带“啸叫”听不见 | 窄带噪声经 Q≈18 带通后能量只剩约 -12dB，实际被主层盖住 | 事件电平要比主层高 6–10dB；用带通包络测量确认事件真的出现 |
| 模板重建后低频变薄 | STFT 块长决定低频分辨率：1024 点时 100–200Hz 只有 2–3 个频点 | 低频重要的声音试 2048/4096 点；但与判定可能相反，需两者都测 |
| 按 RMS 统一后各声部仍然差 10dB | 归一化函数末尾顺手调了"归一化到峰值"，它会把低峰值的纹理**放大**回 0.98，等于抵消 RMS 目标 | 峰值只做**上限**（`peak > cap` 才压），不要用双向的 peak normalize；改完逐个纹理复核 RMS |
| 循环里的事件听出固定节拍（"噗-噼-啪"三声一循环） | 稀疏事件（每秒 0.15 次）被写进 12 秒循环，每圈重复同一组时序 | 纹理只保留连续底噪，事件改为运行时随机排程（指数型随机间隔 + 偶发成簇） |
| 底噪的起伏也每 12 秒重复 | `addBed` 里烘焙的正弦 LFO（0.08–0.6Hz）跟随循环一起重复 | 循环纹理不要烘焙慢速调制；起伏交给运行时随机事件或非周期调制 |
| 参考有“雨点打在物体上”的质感，合成只有噪声墙 | 20ms 帧的能量包络模板把 3–8ms 的撞击抹成能量块，STFT 随机相位重建后只剩雨雾 | **不要直接补“撞击点击”**：按命中密度/电平分位补出来的点击，PM 判定比模板版更不像。参考的雨点感与底纹同源，指标对上≠听感对上；这类差异要换更细的时频重建，而不是叠加离散事件 |
| 火焰像“呼呼的火声”而不是“柴火噼啪” | 旧版用 brown/pink 噪声当底纹，低频占比压倒参考 | 参考篝火的能量几乎全在 2–10kHz 的爆裂上（低频占比 -11dB）；底纹应由**密集微爆裂 + 轻噪声层**构成 |
| 火焰像“零星响指”而不是“持续燃烧” | 底纹近乎静音、事件电平高出中位 21dB（参考只有 5dB） | 底纹必须有声：1ms 帧的中位电平要接近事件电平，事件只比它高 5dB 左右；用“事件电平 p50”而不是只看频段占比来判断 |
| 呼啸像“独立插播的音效” | 呼啸事件只改啸叫门，风量本身不动 | 参考里呼啸出现时整体风量同时高 8dB：用同一条阵风包络同时驱动**整层风量**与啸叫，形状为“轻微→激增→回落→消失”，并允许二次起伏 |
| 阵风“从很低一下跳到很高”、偶尔被硬截断 | 用单个极短时间常数的 setTargetAtTime 冲上去；下一次阵风又在新事件开头 `cancelScheduledValues`，把上一次的尾巴砍掉 | 上升/下降各分 3–4 级、每级 0.3 秒时间常数；调度器记住当前阵风的结束时间，下一次必须排在其后 |
| 程序化底纹怎么调都不像真火 | 参考篝火的“底纹”其实是密集爆裂本身，任何额外噪声层都会露出“噪声感” | 先只保留事件层；需要底纹时再基于事件密度设计，而不是加噪 |
| 补进去的事件完全听不出来 | 包络模板渲染出的原始幅度不可知（可能是 5 倍于 1.0），事件的绝对增益被整体归一化吞掉 | 先用 `normalizeLoudness` 把纹理固定到已知 RMS，再按相对电平补事件 |
| 宽带小事件被算成 +20dB 尖峰 | 对 107 个频点取 **dB 平均**，宽带噪声会把所有频点的 dB 一起抬高 | 测瞬态用**能量平均**再转 dB；dB 平均只适合看音色倾斜 |

> 上述“火焰像呼呼的火声”一条后来被更精确的判据取代（见上一行的“零星响指”），两者是同一现象的两种表现：噪声层太重 → 呼呼声；噪声层全去掉 → 响指声。

## 5. 验收清单

- `judge.py`：候选的 P(Thunder/目标类) 与所用模板的原声同档；干扰类（Rain、Explosion、Music、Drum、Gong）不高于原声。
- `acceptance.py`：越界维度 ≤1，且越界不集中在中高频段（否则是"太亮/太嘶"）。
- `tonality`：中位 ≤0.25，>0.5 的帧 ≤3%。
- 渲染耗时：单条 <200ms（本项目实测约 50–140ms）。
- 页面实测：点击播放无控制台错误；多声部混音不过载。
- **人耳**：A、B 两段分别确认；"像不像"只能由人给结论。

## 6. 什么时候该停

如果**换过一个参数族仍然不移动判定**（例如把频谱、包络、长度、起音各扫一遍，判定都在同一区间），说明缺的不是参数而是表示。此时应回到第 3 步，先确认引擎能否临摹参考；不要继续在同一族参数上微调。

本项目的记录：从零构造包络尝试了六种参数族（几何到达、统计包络、离散 roll、连续随机过程、单元重组、调制谱匹配），最好只到 0.34 且对随机种子敏感；改用"实测模板 + 温和变形"后稳定在 0.29–0.55。

## 7. 已知限制

- 模板来自具体录音，风格受参考集限制；扩充模板需要新的、干净的参考。
- 31.5Hz 频段在 2048 点分析窗下不足一个频点，产品数据里保持静音（为兼容已验收版本）；需要更低的低频时应改用更长分析窗。
- 人声、乐器等有明确基频与发音机制的声音不适用本方法。

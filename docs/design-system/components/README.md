# 组件

这里说明组件的提取边界和文档写法，不维护组件清单。具体组件文档在需要时创建，并在本页索引。

## 什么时候提取共享组件

原生元素与组件封装的选择见 [标签与组件边界](../foundations/semantics.md)。

同时满足以下条件时，才值得提取共享组件：

- 多个页面需要相同的行为和状态；
- 有明确的变体或交互契约；
- 有可复用的状态处理或交互规则；
- 单独维护比重复实现更清晰。

仅视觉相似时，优先复用 token 或局部 class。不要为了统一外观添加转发层或空壳组件。

## 什么时候写组件文档

组件满足任一条件时，建立独立文档：

- 有多个变体或状态，需要说明使用边界；
- 有交互行为或异步状态；
- API 会变化，调用方需要稳定参考；
- 同一组件在多个页面出现，容易产生不一致。

只有一个使用点、没有变体和状态的局部 UI，不单独建文档。

## 文档模板

每篇组件文档使用以下结构：

1. **用途**：解决什么问题，什么时候使用，什么时候不使用。
2. **结构**：组成元素和层级，不含具体页面截图。
3. **变体**：主次、尺寸等正交维度，说明组合规则。
4. **状态**：默认、悬停、选中/激活、禁用、加载、错误等。
5. **行为**：交互、异步、取消、失败和恢复。
6. **内容**：标签、辅助文字和状态文案的写法。
7. **元素与状态**：原生控件类型、状态表现和使用限制。
8. **API/代码**：属性、事件和可复用入口，指向代码事实来源。
9. **相关模式**：与其他组件组合时的规则。

## 变体与状态

- 变体保持正交：主次、尺寸、状态分别表达，不组合出大量特例。
- 状态名称保持一致：default、hover、selected/active、disabled。
- 组件默认值要明确；调用方不需要“先设置某项再使用”才能得到正确行为。
- 组件不隐藏必要的失败、禁用或加载状态。

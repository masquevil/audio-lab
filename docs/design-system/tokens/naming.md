# Token 命名

Token 是设计规则的稳定接口。先确定语义角色，再命名；不要先把具体值写进组件，之后再补名字。

## 分层

| 层 | 职责 | 作用域 |
| --- | --- | --- |
| 全局语义 token | 颜色、排版、间距、圆角、动效、布局 | 整个应用 |
| 局部视觉 token | 单一视觉模块的主题值 | 该模块 |
| 组件局部值 | 只在本组件使用的布局和尺寸 | 组件样式 |

- 全局层只放跨页面复用的语义角色。
- 局部层限制在对应模块，不向全局泄漏。
- 组件只消费 token；具体值不散落在组件中。

## 命名语法

使用 `--{类别}-{角色}-{层级/状态}`：

| 类别 | 示例 | 说明 |
| --- | --- | --- |
| 颜色 | `--color-bg-surface`、`--color-text-secondary` | 按用途，不按页面或组件 |
| 字号 | `--font-size-body` | 按语义角色，不用像素值命名 |
| 行高 | `--line-height-heading` | 按文本角色 |
| 间距 | `--space-4` | 固定比例尺中的档位 |
| 圆角 | `--radius-control` | 按元素层级 |
| 动效 | `--motion-fast` | 按时长角色 |
| 布局 | `--page-gutter-horizontal` | 明确方向和作用域 |

规则：

- 名称表达用途，不表达具体值；不要出现 `--font-size-13` 一类数字别名。
- 变体后缀保持一致：主/次、默认/弱化、`on-*` 等。
- 同一个概念只保留一个名称；语义变化时迁移，不并行维护两个相似 token。
- 间距 token 只用于 gap、padding、margin、inset；元素宽高由组件尺寸表达。
- token 不按页面、组件或一次活动命名。

## 生命周期

1. **确认需求**：先检查现有角色能否复用；只有语义确实不同才新增。
2. **定义名称**：按语法确定类别、角色和变体。
3. **实现**：在全局或局部层定义，消费端替换为语义变量。
4. **迁移**：更新所有引用，删除旧名称，避免长期保留别名。
5. **验证**：检查主题、状态和响应式表现。
6. **记录**：设计取舍写入需求记录；规范文档只保留当前规则。

## 事实来源

- 代码是实现的唯一来源；文档给读者准确的档位与取值，不要求读文档的人再去读代码。
- 同一份值在代码中只定义一处、在文档中只列出一次，不跨文件重复。
- 文档负责解释分类、命名和演进规则；修改取值时同步代码与对应文档。
- 新增或修改 token 的流程见 [参与设计系统](../contributing.md)。

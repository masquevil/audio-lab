# 颜色

颜色按语义角色使用，不按页面、组件或具体色值使用。目标是让同一角色在所有界面保持一致，并让主题变化只影响 token 定义。

## 角色

| 组 | 角色 | 用途 |
| --- | --- | --- |
| 表面 | 页面、表面、控件 | 页面底色、面板/卡片、控件底部 |
| 文本 | 主文本、次文本、反色文本 | 正文、说明、强调色上的文字 |
| 边界 | 边框、阴影 | 分隔、轮廓、层级暗示 |
| 强调 | 强调色、弱强调、`on-accent` | 主操作、选中态、强调表面 |
| 状态 | 危险、成功、警告等 | 错误、完成、提示 |

## 命名

- 使用 `--color-{角色}` 或 `--color-{角色}-{层级/状态}`。
- 背景按层级命名：页面、表面、控件。
- 文本按强调程度命名：主文本、次文本。
- 强调色需要 `on-*` 变体时，明确表达“用在强调色之上的前景色”。
- 不按页面、组件或具体颜色命名，例如不要出现“首页绿”“按钮蓝”。

## 使用规则

- 原始色值只出现在 token 定义中，组件只使用语义变量。
- 先寻找可复用的角色；只有语义不同才新增颜色，不新增页面级色板。
- 一个区域通常只有一个主强调色；主操作、选中态和提示不要各自使用近似色。
- 危险色只用于破坏性操作和错误，不用强调色代替危险色。
- 状态不能只靠颜色表达，必须同时有文字、图标或结构变化。
- 暗色主题保持稳定层级：页面 → 表面 → 控件/反馈，避免同一层级出现多个近似底色。
- 阴影是层级和边界的辅助手段，不承担主要信息编码。

## 可读性

- 正文与背景保持足够对比度；次要文本可以降低强调，但不能难以阅读。
- 选中态、禁用态和错误态仍需保持可辨识，不只依赖颜色差异。

# 标签与组件边界

HTML 标签服务于原生行为和结构，CSS 负责外观，组件负责复用和稳定 API。本项目仅供作者自用，不为读屏、ARIA 或辅助技术建模，标签选择不按“语义正确性”审查。

## 选择顺序

1. **需要什么行为**：先找能提供该行为的原生元素（`button`、`input`、`details`、`a`、`select`）。
2. **需要设计系统统一吗**：如果多处复用、需要统一视觉/状态/动画/受控行为，把原生元素封装进组件。
3. **只是视觉差异吗**：用 class + token；不要为此更换标签。

组件可以并且应该渲染原生元素；设计系统暴露的是组件 API，不是“调用方必须直接写某个标签”。

## 常见映射

| 场景 | 原生基础 | 何时封装组件 |
| --- | --- | --- |
| 动作 | `button` | 需要主次、尺寸、禁用等统一 API |
| 导航 | `nav` + `a` | 需要统一激活态、路由和布局 |
| 折叠 | `details` + `summary` | 需要自定义 marker、动画、受控状态或复用 |
| 单选/多选 | `input` + `label` | 需要统一视觉和组状态 |
| 视图切换 | 按钮/链接 + 选中态 | 需要统一选中和切换逻辑 |
| 卡片/面板/列表项 | `div`；页面区块用 `section` | 需要统一结构、状态或交互时封装 |
| 表格数据 | `table`/`thead`/`tbody`/`th` | 需要排序、固定列等数据网格能力 |
| 布局/装饰 | `div`/`span` | 通常不需要组件 |
| 小字/注释 | `span` + class | 视觉小字用 token，不依赖标签默认字号 |

## 规则

- 有行为的控件优先使用原生元素；不要用 `div`/`span` + 点击事件替代 `button`、`a`、`input`。
- 展示容器不使用 `article` 等语义标签：卡片、面板、列表项统一用 `div`，页面区块用 `section`。
- 标签不承担字号、颜色、布局等视觉职责。
- 不为读屏添加 `aria-*`、`role` 或可访问名称；已有属性不强制清理，用户明确要求无障碍适配时再处理。
- 设计系统不为“统一外形”要求调用方直接写标签；共享组件内部保留原生元素和一致状态。
- 需要自定义样式、动画、受控状态或跨页面复用时，封装组件，而不是在每个调用点重复标签和样式。
- 封装后保留原生行为：点击、展开、禁用和状态变化。
- 原生元素无法满足需求时再自定义，并保持行为一致。

## 两个典型边界

- **`small`**：不是字号工具。视觉小字使用 `span` + class/token。
- **`details`/`summary`**：原生 disclosure，带展开状态；简单场景可直接使用。需要统一 marker、动画、受控状态或复用时封装组件；组件内部可继续使用 `details`/`summary`，或按需要自定义。注意 `summary` 内的复杂结构会被简化。

## 验证

- 鼠标和触摸下能否完成操作。
- 组件封装后行为是否与原生元素一致。
- 视觉状态是否完整，而不是只复制外观。
